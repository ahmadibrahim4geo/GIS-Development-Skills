# قبول فحص متطلبات المشروع من جذره

21 نوفمبر 2026 بتوقيت القاهرة · المراجعة المحلية r8

فحص البداية يأخذ هدف التطوير من الخطة التي فهمها الوكيل. يجمع قائمة
الأدوات والحزم المعلنة من جذر المشروع. يعرض لكل أداة سبب الاستعمال وما
رُصد عن وجودها ورابطها الرسمي. يحتفظ المحرر الموجود بدوره في تحرير المصدر
طوال المشروع. البناء والمعاينة وتصميم الواجهة حالات مستقلة.

## الملاحظات الفعلية

| السيناريو | النتيجة |
| --- | --- |
| مشروع جديد | تلقّى الأمر هدف WPF وإصدار .NET 10 واسم حزمة من الخطة. اقترح .NET CLI للبناء. احتاج التصميم المرئي تحققًا منفصلًا. بقي الجذر المخطط غير منشأ. |
| مشروع قائم | قرأ الأمر حلًا حقيقيًا بصيغة .sln ومشروعًا تحته، واستخرج net10.0 من ملف المشروع. بنى SDK المثبّت الحل وظهر ملف DLL. تطابقت بصمات ملفي المشروع والحل بعد الفحص والبناء. |
| أداة محددة غائبة | عينة معزولة طلبت Visual Studio لعمل مخصوص، وأظهرت تعليق هذا العمل. ظل خيار .NET CLI للبناء وRider المثبت للتحرير وفق بيانات العينة. فتح Rider الحقيقي غير مختبر. |
| SDK محدد غير متاح | عينة global.json ذات rollForward معطّل علّقت البناء، واحتفظت بإمكانية فحص المصدر واستعمال المحرر المرصود. |
| البيانات والملفات | استخرجت اختبارات الفهارس أسماء حزم من الحقول المعلنة. استُبعدت الروابط المباشرة داخل قيم الإصدارات وملفات testing data. جُرّب الأمر من حزمة مفكوكة. |

يُعرض البديل كمرشح بعد مطابقة تنسيق المشروع وإطاره وإصداره. يظل بناء
العينة الأصلية واختبار الملحقات والمصمّم وفتح الحل في عميل مختلف
اختبارات مستقلة. إذا لم يتوفر المتطلب المحدد، يعرض الوكيل الرابط الرسمي
والتأثير على خطوات الخطة، ويطلب قرار المستخدم قبل التثبيت أو تغيير النهج.
الشغل الذي لا يعتمد على هذه الخطوة يستمر.
