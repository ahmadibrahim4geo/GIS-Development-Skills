# خطة توسيع تطوير تطبيقات GIS للموبايل والويب

المراجعة r1 · مسودة للموافقة · مستودع GIS Development Skills

## المطلوب

يختار الأيجنت مسارًا واضحًا لما المستخدم يطلب موقع GIS، تطبيق Web GIS أو PWA، أو تطبيق موبايل GIS أصلي. يبدأ المسار بمصادر وأمثلة تناسب المشروع، ويوصل إلى تشغيل واختبارات تدعم الادعاءات. نستخدم الأدوات المفتوحة بصفة افتراضية ونوثّق الشركات والخدمات التجارية حسب نوع الاستخدام المسموح.

المقترح هو توسيع مهارتي [Geospatial Web Mapping](../../../skills/geospatial-web-mapping/SKILL.md) و[GIS Mobile Application Development](../../../skills/gis-mobile-application-development/SKILL.md) وإعادة استخدام المهارات المشتركة. نطاق التنفيذ المحتمل يشمل التوجيه، الكتالوجات، الأمثلة والاختبارات، مع الحفاظ على الشغل الحالي وبيانات المستخدم وأصول الموقع.

## الوضع الفعلي

- فحص النسخة المنشورة محليًا عند `8747283` وجد 193 مشروعًا، و53 سجل خدمة، و17 مصدر كود، و5 وصفات كود مفهرسة. الكتالوج يتضمن بالفعل MapLibre GL JS وMapLibre Native وOpenLayers وLeaflet وCesiumJS وQField وMergin Maps وMapStore وLizmap وGeoNode وPostGIS وMartin وPMTiles. استكمال الاستخدام والأمثلة أفضل من إضافة صفوف مكررة لها.
- مسار الموبايل عندنا فيه أدلة GNSS والمزامنة والتخزين والأمان، ومثال صناعي للمزامنة. مسار الويب فيه اختبارات قراءة GeoJSON من متصفح ومراجع عرض وبيانات. الفجوة هي رحلة كاملة قابلة للتكرار لكل نوع تطبيق، تبدأ من اختيار المرجع وتوصل لاختبار الواجهة والتخزين وقراءة الناتج.
- فحص Modern Web Guidance وUI/UX Pro Max رجّع `READY`. استخدمت دليل `accessibility` لتحديد وصول لوحة المفاتيح والتركيز، ومخرجات UI/UX لتحديد مقاسات لمس تراعي وحدات كل منصة. البحث في Modern Web Guidance عن التخزين دون اتصال لم يُرجع دليل Service Worker مطابقًا، فمتطلبات PWA مأخوذة من مرجع الويب المختص. [دليل PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)
- ظهر Node وJava و.NET في فحص أوامر الجهاز. لم تظهر `adb` أو `flutter` أو `xcodebuild` على PATH. نتحقق من SDK والجهاز قبل أي ادعاء بقبول Android أو iOS. اختبار جلسة Codex الجديدة الذي تعذّر في الدمج السابق يبقى اختبارًا مستقلًا.

GIS Code Discovery يحدد الأمثلة القابلة للتكييف، وGeospatial API Integration يملك ربط الخدمات، وتُستدعى مهارات البيانات وCRS وPostGIS عند الحاجة. كل مشروع يثبت اختياراته من الواجهة إلى المحرك إلى البيانات.

## ترتيب التنفيذ

1. **التوجيه وإغلاق فجوات الكتالوج.** أضف أمثلة توجيه بالعربي والإنجليزي تميّز موقعًا من تطبيق ويب، وPWA من تطبيق أصلي. حدّث موجود الكتالوج أولًا وأضف المصادر اللازمة من [دفعة المراجعة](SOURCES.md)، وسجّل الدور والمنصة والرخصة والحساب المطلوب وقيود الاستخدام. اربط أمثلة الكود بملفات أو وصفات محددة تحت السجلات الحالية. راجع مرشحي المهارات خارجيًا قبل أي تفعيل، وحدد الفرق الذي سيقدمه كل مرشح عن مهاراتنا.
2. **مثال Web GIS قابل للتشغيل.** اقترح تطبيق HTML/JavaScript صغيرًا مع MapLibre GL JS، وبيانات GeoJSON صناعية ثنائية اللغة لنقاط معاينة. حمّل طبقة، اختر نقطة، عدّل حقلًا، احفظ وصدّر، ثم أعد قراءة الناتج بشكل مستقل. يبدأ بمصدر محلي ثابت؛ اختبار نطاق أكبر يضيف PMTiles أو Martin عند الحاجة. استخدم OpenLayers كمسار قرار عندما تكون الإسقاطات أو خدمات OGC أو أدوات التحرير هي الأولوية. تتبع الإحداثيات والـID والحقول واللغة من الإدخال للتصدير.
3. **توسعة PWA حسب الحاجة.** أضف manifest وService Worker وتخزينًا محليًا للبيانات والموارد المسموح بتخزينها. اختبر التثبيت على المنصات المعلنة، وفتح التطبيق بعد فصل الشبكة، وإصدار التخزين واستعادته أو رفضه عند نقص المساحة. لو المشروع يحتاج صلاحيات خلفية أو تدفق GNSS أثقل، قيّم المسار الأصلي.
4. **مثال GIS أصلي للموبايل.** ابدأ بتطبيق Android صغير بـKotlin وMapLibre Native كاقتراح أول، بعد التحقق من SDK وإصدار المحرك والجهاز. استخدم نفس مخطط النقاط الصناعي، مع إذن موقع أمامي اختياري، حفظ محلي وعرض حالة الدقة، تعديل دون اتصال، قتل التطبيق وإعادة فتحه، وتصدير تقرؤه أداة مستقلة. اختبر رفض الإذن وتشغيل التطبيق بدونه. أضف اختبار مزامنة بتعارض وإعادة محاولة بعد إثبات الحفظ المحلي. اعمل قبول iOS مستقلًا على Apple/Xcode، وقيّم Flutter أو React Native إذا كانت مشاركة واجهة الموبايل مطلبًا فعليًا.
5. **دليل الشركات والبدائل المفتوحة.** أضف مقارنة موثقة لكل منتج وSKU بين الكود المتاح، البيانات المستضافة، الحصة المجانية أو التجريبية، شروط الإنتاج، الكاش أو الأوفلاين، النسب، وإجراء إيقاف التكلفة عند الحد. اختبر مسارًا بمزوّد واحد فقط إذا توفرت الصلاحيات وحساب مناسب، واستخدم مسار البيانات المحلية في الاختبار الأساسي. بقية المزوّدين يحتفظون بحالة دليل أو عينة مصدر لحين التحقق من التشغيل.
6. **القبول والتوزيع.** أظهر مسارات Web GIS وPWA والموبايل في الصفحة الرئيسية والـExplorer وREADME باللغتين، ومتطلبات البناء والاختبارات أظهرها بجانب كل نموذج. أعِد توليد العدادات من JSON وسجل المهارات. اختبر المتصفح والمقاسات واللغة والتصدير، وAndroid وiOS كلًا على الجهاز المستهدف، ثم طبّق التوزيع المتحقق منه بعد موافقة النطاق.

## قبول كل دفعة

أماكن التغيير المقترحة تشمل مهارتي الويب والموبايل والراوتر، و`references/project-catalog.json` للمشروعات، و`references/gis-code-sources.json` و`references/gis-code-recipes.json` لأمثلة الكود، و`references/free-geospatial-apis.json` للخدمات التي تنطبق عليها شروط الكتالوج. المقارنات التجارية مكانها الدليل مع روابط الشروط. تمتد الأمثلة من `examples/mobile-gis/` وملفات القبول الموجودة تحت `native_tests/`. أي مجلد جديد يوثّق ضمن بنية المشروع عند اعتماده.

- **الفهرس:** كل إضافة لها مصدر رسمي، مراجعة رخصة وتوافق، نوع وتاريخ، وبيان واضح لحالة الاختبار. سجّل مصدر الكود ورخصة البيانات وشروط الخدمة لكل استخدام.
- **الويب:** جلسة متصفح تشغّل الخريطة والأزرار والتحرير والتصدير. تنقل لوحة المفاتيح، RTL/LTR، عرض ضيق وواسع، واتساق إحداثيات وحقول الملف المقروء. قياس PWA منفصل عند طرحه.
- **الموبايل:** نسخة مبنية تشتغل على جهاز أو محاكي مع سجل الإصدار والبيئة، واختبار ميداني على الجهاز الفعلي قبل ادعاء جاهزية GNSS، والتوثيق المنفصل لمسارات رفض الإذن، إعادة التشغيل، والمزامنة. قبول كل منصة أو منصة غير متوفرة يُسجَّل بحالتها.
- **المزودون:** تُستدل على الشروط من وثائق المزود في تاريخ التحقق. أي مفتاح أو بيانات حقيقية أو حصة مدفوعة تحتاج إذنها الخاص، وتبقى خارج سجل النتائج.

التخطيط الحالي يشمل الفحص والبحث وتسجيل المرشحين. يبدأ التنفيذ أو التثبيت أو النشر بعد مراجعة النطاق. المرجع الخارجي أو الفحص الثابت يُثبت توفر المصدر وبنية التخطيط. أدلة المتصفح والأجهزة تُجمع في مراحل التنفيذ.
