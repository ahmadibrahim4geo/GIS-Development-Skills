# كيفية استخدام GIS Development Skills

**ابدأ من:** [طريقة الاستخدام بالصفحة الرئيسية](../index.html#how-to-use) · [المستكشف الكامل](../explorer.html#get-started) · [English](HOW_TO_USE.md)

المستودع يضم ملفات تعليمات للوكلاء البرمجيين (`SKILL.md`)، ومراجع وأمثلة واختبارات لتطوير تطبيقات نظم المعلومات الجغرافية. **ليس برنامج GIS مستقلًا، ولا اشتراك ذكاء اصطناعي، ولا وكيلًا يعمل من داخل صفحة HTML.**

## المسار الأول — باستخدام وكيل برمجي

### الخطوة 1: حدد مشروعك وبيئة التشغيل
وضح للوكيل نوع المشروع: ArcGIS Pro أو ArcMap أو QGIS أو تطبيق سطح مكتب أو خرائط ويب أو KML/KMZ أو معالجة بيانات واستشعار عن بُعد. اذكر الإصدار ونظام التشغيل وصيغ البيانات ونظام الإحداثيات (CRS) والنواتج المطلوبة وأي شروط للترخيص. احتفظ بنسخة آمنة من المشروع واستخدم Git إن أمكن.

### الخطوة 2: ثبّت المهارة داخل بيئة متوافقة
تحتاج إلى Node.js وإلى وكيل برمجي يدعم Agent Skills وإلى مراجعة صلاحيات أداة [Skills CLI](https://github.com/vercel-labs/skills). افتح Terminal داخل مجلد المشروع:

```sh
npx skills add ahmadibrahim4geo/GIS-Development-Skills --skill gis-development
```

عند الحاجة إلى تخصص محدد، مثل KML/KMZ:

```sh
npx skills add ahmadibrahim4geo/GIS-Development-Skills --skill kml-kmz-engineering
```

راجع رسائل التثبيت وطلب الصلاحيات، وقد تحتاج بعض الوكلاء إلى طريقة تثبيت مختلفة. التثبيت من المستودع المنشور على `main` **لا يتضمن بالضرورة المهارات الموجودة فقط داخل Pull Request لم يُدمج**. الأمر لا يثبت ArcGIS أو QGIS ولا يوفر اشتراك نموذج ذكاء اصطناعي.

### من البرومبت إلى هدف واضح وخطة تنفيذ

الوكيل البرمجي المتوافق يقرأ طلب المستخدم أولًا، ويحدد **الهدف النهائي**، والمخرجات المطلوبة، وبيئة المشروع، والقيود، و**كيف سنتأكد إن الناتج نجح بالفعل**. بعد كده يعرض مهام مرقمة ومقاييس نجاح للمراجعة، ويوجه المعتمد منها من [مهارة فهم الطلب](../skills/prompt-intent-orchestrator/SKILL.md) إلى [الموجّه العام](../skills/gis-development/SKILL.md) ثم المهارات التخصصية مع فحص الأمان والتوافق والتوثيق. اقرأ [عقد سير العمل الموحد](../references/repository-wide-skill-orchestration.md).

[معالج المشاريع](../project-wizard.html) بيوفر حقولًا للهدف ومعايير النجاح بالعربي والإنجليزي، ويُصدّر **خطة Markdown للمراجعة وملف JSON كمسودة** متوافقة مع أداة تنظيم المهام. تنزيل JSON يتطلب الهدف ومعايير النجاح؛ لا يعتبر موافقة ولا يشغّل الذكاء الاصطناعي. ويمكن ترتيب المهام من خطة JSON راجعها الوكيل دون تنفيذها:

```sh
python scripts/intent_router.py --text "عايز أعمل برنامج GIS يفتح ملفات KMZ" --format json
python scripts/intent_router.py --plan examples/intent-orchestrator/example-plan.json --workflow --format json
```

الأمر الأول مجرد اقتراحات كلمات مفتاحية، والثاني يولد Workflow مرتبًا بناءً على هدف مكتوب في الخطة؛ لا يمنح صلاحيات ولا يغير الملفات.

### أربع مهارات لتطوير جودة التطبيقات

لو هدف المستخدم يتعلق بواجهة التطبيق أو فحص تشغيله، يمكن اختيار [جرد الأوامر](../skills/gis-ui-command-audit/SKILL.md)، [اختبارات Desktop الفعلية](../skills/gis-desktop-e2e-testing/SKILL.md)، [تشخيص تدفق البيانات](../skills/gis-data-flow-diagnostics/SKILL.md)، و[تصميم واختبار UI/UX](../skills/gis-ui-ux-design-testing/SKILL.md) بصورة مستقلة حسب المهمة. [دليل التكامل](../references/gis-ui-quality-coordination.md) يمنع تكرار المسؤوليات. يوجد خيار مخصص في [معالج المشاريع](../project-wizard.html).

الأمثلة التالية اختبار *صناعي آمن* لا يفتح تطبيق GIS أو واجهة Windows:

```sh
python scripts/gis_ui_command_audit.py --root examples/ui-command-audit/fixture
python scripts/gis_data_flow_diagnostics.py --trace examples/data-flow-diagnostics/trace.example.json
```

لا تعتبر نجاح فحص الشفرة أو البيانات الوصفية إثباتًا لنجاح أوامر المحرك أو الـWebView2 الحقيقية.

### الخطوة 3: اشرح المطلوب بطريقتك واطلب خطة قبل التنفيذ

> عندي تطبيق GIS محتاج تحسين استيراد KML/KMZ مع الحفاظ على الأيقونات والألوان والمجلدات والأنماط الأصلية. افحص الملفات أولًا واعرض خطة مرقمة بالمهام والمخاطر والنواتج والاختبارات لاعتمادها. بعد الموافقة نفّذ المعتمد فقط، وسجّل كل خطوة وتصحيح وإلغاء في سجل تطوير المشروع. اختبر المخرجات فعلًا، ووضح الوظائف التي لم تُختبر داخل البرنامج.

المفترض أن الوكيل المتوافق يستعين بمهارة [فهم الطلبات](../skills/prompt-intent-orchestrator/SKILL.md)، والـ[GIS Router](../skills/gis-development/SKILL.md)، و[الأمان](../skills/gis-security-guardian/SKILL.md)، ويستخدم [سجل التطوير](../skills/agent-development-journal/SKILL.md) **إذا كان مثبتًا ومربوطًا بنقاط التنفيذ فعليًا**. ملفات Skills لا تؤكد الموافقة بمفردها ولا تراقب الأوامر تلقائيًا.

### الخطوة 4: راجع النتائج قبل قبول العمل
اطلب تقريرًا يبين: الطلب الأصلي، ورقم الخطة المعتمدة، والمهام المنفذة، والملفات أو الـcommits التي تغيّرت، وأوامر الاختبارات ونتائجها الفعلية، وأي اختبارات متعذرة، ومراجع المصادر والتراخيص. **نجاح اختبار Python ثابت لا يعني أن زرًا داخل ArcGIS أو QGIS أو تطبيق مكتبي يعمل فعلًا.** يمكن استخدام [نموذج تقرير القبول](../templates/GIS_ACCEPTANCE_REPORT.md).

لا تسمح بحذف بيانات أو إرسال ملفات أو نشر أسرار أو تعديل نتائج GIS حساسة دون صلاحية واضحة ومراجعة مناسبة.

## المسار الثاني — الاستخدام بدون وكيل

1. افتح [قائمة المهارات](../explorer.html#all-skills) واختر تخصصك ثم اقرأ `SKILL.md` والمراجع المرتبطة.
2. راجع [الأمثلة العملية](../examples/README.md) والقوالب: [ArcGIS Pro Toolbox](../templates/arcgis-pro-toolbox.pyt)، [ArcMap](../templates/arcmap-script-tool.py)، [QGIS Processing](../templates/qgis-processing-algorithm.py).
3. تحقق من [سياسة المجانية والتراخيص](../references/free-first-policy.md) وحقوق استخدام المكتبات والبيانات الخارجية.
4. طبّق على نسخة من المشروع، واختبر البيانات والإحداثيات والوحدات والمخرجات ببرنامج GIS الفعلي، ثم وثّق التعديلات.

## أسئلة شائعة

**ثبت المهارة، فين البرنامج؟** التثبيت يضيف تعليمات إلى وكيل برمجي متوافق، وليس ملف EXE أو إضافة ArcGIS جاهزة. تحتاج إلى وكيل وأدوات فعلية وتشغيل واختبار.

**ينفع أتكلم بالعامية المصرية؟** أيوه، وضّح هدفك بالشكل المعتاد واطلب خطة من الوكيل يراجعها معاك قبل تغيير ملفات المشروع.

**هل الوكيل يفتكر شغل الجلسات القديمة؟** إذا تم حفظ سجل التطوير داخل المشروع ويملك الوكيل صلاحية قراءته والتحقق منه. لا تعتمد على ذاكرة المحادثة وحدها، ولا تعتبر التقارير دليلًا كافيًا على نجاح الكود.

**لو طلبت تعديل أو إلغاء خطوة قديمة؟** تتم إضافة تقرير جديد برقم مستقل مرتبط بالتقرير الأصلي دون حذفه. التراجع الحقيقي عن الكود عملية أخرى تحتاج تنفيذًا آمنًا واختبارات.

**هل كل المراجع والخدمات مجانية؟** لا. بعض المصادر مجانية بقيود أو تتطلب تراخيص. راجع شروط أصحابها.

**إزاي أبلّغ عن خطأ؟** افتح [GitHub Issue](https://github.com/ahmadibrahim4geo/GIS-Development-Skills/issues) واذكر الإصدار والخطوات والنتيجة المتوقعة والفعلية من غير أسرار شخصية.

هذه الصفحة دليل استخدام، وليست إثباتًا لتشغيل تطبيق GIS أو وكيل ذكاء اصطناعي داخل المتصفح.

لدمج محرك QGIS في **تطبيق مستقل** وليس إضافة داخل QGIS، استخدم `qgis-engine-integration` ودليل [هندسة المحرك](../references/qgis-engine-integration.md) و[مثال PyQGIS الأصلي](../examples/qgis-engine/README.md)، مع مراعاة التراخيص ونسخ المكتبات واختبارات التشغيل.

## إثبات الإنجاز ومطابقة التقرير مع الخطة

يوضح [عقد المسؤوليات](../references/repository-wide-skill-orchestration.md) مَن يفهم الطلب ومَن يوجّهه ومَن ينفّذ ومَن يتحقق ومَن يوثّق. افحص وصول المهارات بالأمر `python scripts/audit_skill_graph.py`. وعند تسليم مهمة فعلية يجب الحفاظ على `request_id` و`revision` ومعايير القبول كاملة ومطابقتها مع تقرير DoneProof:

```bash
python scripts/verify_completion.py report.json --plan reviewed-plan.json --require-verified
```

نتيجة PASS تعني أن **التقرير متوافق بنيويًا مع الخطة**، لا أن البرنامج اشتغل فعليًا أو أن السجلات الخارجية سليمة دون فحصها. تُسجّل الاختبارات الأصلية غير المنفذة NOT RUN.

## البحث عن الصور والشعارات ودمجها

اطلب: «ابحث عن صورة مناسبة لكل اختيار، واستخدم الشعارات الرسمية للمصادر، ووسّع البحث على الإنترنت حسب الحاجة، وادمج الصور محليًا مع توثيق المصدر واختبار الحجم». يختار الموجّه [مهارة الأصول البصرية](../skills/visual-asset-discovery-integration/SKILL.md) ويتعاون معها صاحب الواجهة والمنصة. راجع [الطلب الجاهز والأمثلة](../examples/visual-assets/README.md) و[المصادر والمهارات المساندة](../references/visual-asset-sources.md). تستخدم المهارة أدوات البحث والتنزيل أو التوليد الموجودة فعلًا لدى المضيف.

## اطلب مخططًا تفاعليًا عند الحاجة

اطلب من نفس الوكيل: «اشرح بنية مشروعي ومسار الأوامر والبيانات في مخطط تفاعلي». يختار موجّه GIS [مهارة المخططات](../skills/gis-architecture-visualization/SKILL.md)، ويجمع المختص الحقائق، ثم يجهّز الوكيل أداة Archify الخارجية ضمن الصلاحيات ويعيد رابط HTML. افتح الرابط لاستكشاف المكونات والمسارات، واطلب تعديلاتك في نفس المحادثة. تظهر أمثلة قابلة للنسخ في [الصفحة الرئيسية](../index.html#architecture-visualization). راجع [دليل التشغيل والقيود](../references/archify-integration.md) لتوفر المتصفح ودعم العربية وحدود الأدلة.
