# مراجعة وإصلاح فهم الطلب المعماري — 5 نوفمبر 2026

الهدف: أن يحافظ مسار GIS Development Skills على معنى طلب مثل «حوّل أدوات QGIS إلى ribbon واربطها بمحرك واجهة»، ثم يختار المسؤول عن التنفيذ وحدود الربط ومعايير التحقق. تحوّل نطاق العمل من التدقيق والاقتراح إلى التنفيذ بعد توجيه المستخدم الصريح بالقيام بالعمل اللازم.

## موضع الفجوة والتصحيح

| الفجوة المرصودة قبل التعديل | التغيير المنفذ |
| --- | --- |

لم تُضف مهارة مكررة. جرى ربط المهارات الموجودة بعقد واضح في [مرجع الواجهة والمحرك](../references/ui-engine-architecture-contract.md)، مع إبقاء [router](../skills/gis-development/SKILL.md) مختصرًا وتفصيل القرار في [Decision Tree](../references/agent-decision-tree.md).

## كيف يتغير سلوك المسار

1. يحدد المضيف ما الذي يريد المستخدم تغييره وما الذي يجب الحفاظ عليه: البيئة الحالية، بيئة التسليم، الواجهة، محرك العرض، ومحرك الحساب الجغرافي.
2. يختار بين إعادة تنظيم الأدوات، نقل shell الواجهة، دمج محرك، أو استبداله. لا يغيّر مكتبة أو محركًا لمجرد ورود اسم UI.js.
3. يحدد متخصصًا واحدًا مسؤولًا عن كل مهمة، ويضيف تدقيق الأوامر أو تدفق البيانات أو اختبارات الواجهة بحسب المطلوب.
4. يُرفق جرد الأوامر وعقد التدفق ومصادر الإصدارات. ما لم يُكتشف بعد يبقى `unresolved` ويظهر كحاجة إلى فحص قبل التنفيذ.
5. يحافظ compiler على هذه المعلومات، ويترك الصلاحيات والتنفيذ والتحقق الفعلي للمضيف والمتخصصين.

المهارة توجيه للمضيف وليست خدمة تعمل في الخلفية. السكربت المحلي لا يستدعي الوكلاء أو QGIS تلقائيًا، ولا يحوّل JSON إلى إذن تنفيذ. نجاح الاختبارات يثبت السلوك المحلي المحدد الذي شُغّل، ولا يضمن فهم كل صياغة مستقبلية.

## تفسير تدفق البيانات

المسار المطلوب في تصميم نقل أوامر الواجهة هو:

```text
Ribbon / اختصار لوحة المفاتيح
  → هوية الأمر وربطه بالمعالج
  → التحقق من الطبقة والسياق والمعاملات
  → adapter / worker عند الحاجة
  → محرك GIS
  → نتيجة أو خطأ موضحان بعقد
  → قبول النتيجة وتحديث حالة الطبقات والخريطة والواجهة
  → حفظ وإعادة قراءة مستقلة عندما يكون الحفظ ضمن النطاق
```

أضيف [مدقق التدفق](../scripts/validate_architecture_flow.py) للتحقق من بنية التصريح: معرفات فريدة، أطراف موجودة، تطابق قائمة الأوامر مع خرائط النقل، ومسارات رجوع متصلة. لا تكفي حافة result أو state منفصلة عن العملية. تتطلب العمليات غير المتزامنة وصف التقدم والإلغاء والخطأ والتعافي ومالك التنفيذ. يتطلب الحفظ مسار إعادة قراءة متصلًا بالمخرج المحفوظ.

يوضح [مثال خطة QGIS ribbon](../examples/architecture-visualization/qgis-ribbon.plan.json) و[تدفق Buffer](../examples/architecture-visualization/qgis-ribbon.flow.json) ذلك بصورة مقترحة فقط. أسماء الأوامر توضيحية، ولم تُكتشف من تطبيق QGIS حقيقي. مواصفة التدفق مستقلة عن صيغة Archify، وتُحوَّل إلى صيغته بعد اكتشاف نسخته الفعلية؛ لم يُنتج رسم Archify في هذا العمل.

## حالات الاختبار

| الطلب أو الحالة | السلوك المثبت أو التحقق المطلوب |
| --- | --- |
| «حوّل واجهة QGIS إلى ribbon مع الحفاظ على الأدوات» | يظهر احتياج مراجعة معمارية؛ لا يُفترض plugin أو تطبيق مستقل من كلمة ribbon. |
| «حوّل أدوات QGIS إلى ribbon واربطها بمحرك واجهة UI.js» | تُحفظ نية الربط؛ تبقى هوية UI.js غير محسومة، ولا يُثبَّت بديل مشابه بالاسم. |
| `Build a standalone QGIS app with UI.js ribbon` | يظهر تنبيه معماري وتلميح Desktop؛ يحدد المضيف دور QGIS وحدود الربط قبل التنفيذ. |
| `Explain the data flow from UI.js ribbon to QGIS processing and map refresh` | لا يُفترض plugin من Processing؛ يُكشف احتياج تتبع البيانات. |
| `Create QGIS ribbon button` | لا يُرشَّح مثال ArcGIS Pro للتنفيذ؛ عدم وجود وصفة QGIS ribbon ملائمة يبقى نقصًا معلنًا. |
| `Create ArcGIS Pro SDK ribbon button` | يبقى المسار الصحيح ومثال SDK متاحين. |
| «غيّر لون زر ribbon» | لا يُفرض المسار المعماري الكامل على تعديل صغير. |
| خطة تحتوي قيودًا وعقد UI ومحرك ومعرف أمر وعقود I/O | تُحفظ بعد compilation، وتُرفض الحقول المعمارية غير الصحيحة والمراجع الخارجة عن المشروع. |
| تدفق بلا نتيجة أو خطأ أو تحديث حالة متصل | يرفضه المدقق البنيوي. |
| أمر محفوظ في خريطة النقل بلا مسار طلب مرتبط به | يرفضه المدقق؛ جرد معلن وحده لا يثبت التغطية. |
| مكوّن غير متحقق أو عقد مفقود | تُقبل مسودة المراجعة، وتظهر `NEEDS_DISCOVERY`؛ لا تُستنتج صلاحيات أو نتيجة GIS. |

اختبارات المعالج تشغّل JavaScript الفعلي في Node لفحص الترجمة وتغيير المدخلات والتصدير، ثم تمرر المسودات المعمارية إلى compiler. لا تُعد هذه اختبارات عرض بصري في المتصفح.

إعادة الفحص:

```bash
python scripts/intent_router.py --plan examples/architecture-visualization/qgis-ribbon.plan.json --workflow --format json
python scripts/validate_architecture_flow.py examples/architecture-visualization/qgis-ribbon.flow.json

python scripts/validate_skill_pack.py
python scripts/build_manifest.py --check
```

الأوامر أعلاه تستخدم Python 3 حقيقيًا. في هذه البيئة استُخدم الملف التنفيذي المثبت مباشرة لأن alias الخاص بـWindowsApps لم يبدأ. لم يُغيَّر PATH أو تثبيت Python.
